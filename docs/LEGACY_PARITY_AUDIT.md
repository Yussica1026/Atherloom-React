## 从旧工作日志复核出的同类错误

| 旧版曾犯的错误 | React 检查与修复 |
| --- | --- |
| 测试连接只检查格式，错误 Key 也成功 | Android 原生测试现在真实调用所选模型，且探测不强开 thinking；模型拉取也真实访问上游 |
| 保存过 Key 后编辑、测试、拉模型仍要求重填 | 编辑态携带来源线路 ID，原生加密存储按 ID 复用 Key，留空保存不擦除 |
| 设置快速连续保存时旧响应覆盖新值 | 保存操作序列化并用 revision 丢弃迟到响应 |
| 旧后端字号要求 85–130，前端误发 0.85–1.3 导致 422 | React 保存整数百分比，同时兼容读取两种历史单位 |
| 设置遮罩层挡住所有点击 | React 设置面板有独立层级与触摸回归；结构化问题卡也验证 44px 点击目标和选中反馈 |
| 华为 WebView 在 0.7 秒前取消长按 | 改为旧版最终验证过的 320ms 独立触摸计时，不把长按直接等同删除 |
| 删除成功后旧标题/正文残留，或删唯一会话又造同名假会话 | 删除同一帧乐观清空；成功后保持空白或安全打开同人格下一条，失败才恢复；批量清空同样按人格限定 |
| 人格切换与打开对话竞态导致串线 | 所有导航请求使用统一代次守卫，并在载入前后二次核对人格 |
| 失败回答进入重 Roll 版本，成功后显示错误的版本数 | `error`/`pending` 回答不进入可选时间线；重新 Roll 先移除同父消息的失败气泡 |
| 修改/删除消息后旧摘要仍把内容送回模型 | 本机修改、删版本、删全部版本和分支均清空摘要及归档消息 ID；React 状态同步作废摘要 |
| 消息模板改写了气泡和本地原文 | 只在组装模型请求副本时套模板，保存与显示始终保留原始用户文字 |
| 自动压缩抢占首帧，看起来点发送无反应 | 先渲染 pending/busy，再等待两个 animation frame 才开始压缩和网络前置工作 |
| PDF.js Worker 路径重复、错误销毁 document | 使用固定本地 Worker URL，并销毁 loading task；契约测试禁止退回“请转 TXT”的假修复 |
| 共读乱码、书签存了但跳不回 | UTF-8 异常时回退 GB18030；书签/批注均恢复滚动位置 |
| 角色剧场进入时误开第一篇故事 | 默认进入“新故事”；续写结果写回当前剧本，不只留在主聊天 |
| 备份间接带出整个 localStorage 和秘密 | 排除原始本机状态块，逐项导出允许数据；搜索 Key、线路 Key、MCP 密钥统一脱敏 |
| Service Worker 更新强制刷新进行中的聊天 | 新 Worker 只在下次打开接管，不调用 `skipWaiting`/自动重载 |
| HTTP 错误统一成“连接失败” | 浏览器与 Android 均保留 HTTP 状态码和上游详情 |
| Android 返回键直接退出，未先关浮层 | 返回事件按语音、压缩、空间、欲望状态、设置、侧栏顺序消费，再考虑 WebView 历史或退出 |
| Android 本机“流式”实际等待整段结果 | Standalone 增加独立原生上游 SSE 桥；流式增量送入同一消息节点，非流式才等待全文 |
| 主聊天漏传 thinking、思考区默认折叠像是消失 | 每次请求显式携带当前线路 thinking；历史与流式思考默认展开，用户仍可收起 |
| 取消 Android 文件保存后失败提示常驻 | 提示提供关闭按钮，并在 6 秒后自动清理 |

| React 附加状态保存把 API 日记、留言、梦库或唤醒任务覆盖成旧缓存 | API / Standalone 存储继续拥有这些记录；React 只保存计划、审计和未读便笺等附加字段。连接 FastAPI 未加载完成时不展示本机缓存 |
| 旧唤醒已重试三次仍迁成 pending，或旧镜像覆盖完成状态 | `attempts >= 3` 迁为 `error`；canonical 与 mirror 合并时 `done` 永远高于错误、取消、处理中和待执行，双方都为 `done` 时才比较新鲜度 |

## 明确的平台边界

- 扫描图片型 PDF 没有文字层时会明确报错；本轮没有加入 OCR。
- v0.2.3 的 Android 输入优先使用原生系统识别，浏览器回退仍使用 Web Speech，系统 TTS 也取决于设备服务与授权；MiniMax 只提供 TTS 输出。自动化已覆盖权限拒绝、单轮互斥和清理，但真实 Android 权限弹窗、厂商识别服务及音频播放仍待真机。
- AI 定时日记在应用打开时到点执行；WebView 被系统彻底关闭后不能常驻，错过的计划会在下次打开时补写并审计。其隐藏临时会话即使删除失败也保持不可见，并在下次载入继续清理。
- 留言板的 10 分钟 AI 唤醒仅由 Android Standalone 适配层调度；有可用线路时会说明到点执行与应用关闭后下次打开补做，没有线路时明确要求先配置。连接旧 FastAPI 只显示服务器返回，不会把既有 CRUD 和后端 AI 工具写入描述成拥有本机租约、重试或定时唤醒。
- React Standalone 的主聊天日记 / 留言板工具循环已完成：严格 schema 与运行时校验，写权限默认 `ask`、可设 `deny`，工具只能作用于当前人格；OpenAI / Anthropic 原生结构化调用可读写，文本 DSML 仅可读取留言。循环最多 12 轮、总计 12 次调用、每轮最多执行 4 次，服从总超时与取消；写入按用户消息、调用 ID 和内容幂等，所有结果产生工具事件，密封写入后最终回复固定且不携带推理或正文。
- 普通主聊天不接收密封日记或密封留言正文；密封日记只在隔离的私人日记生成模式供所属人格维持内在连续性，输出直接密封保存，界面仅显示数量。
- 梦库按旧版设计没有主聊天工具；生成、草稿编辑、保存和认领始终是独立流程，认领不表示自动进入聊天上下文。
- 连接旧 FastAPI 时，全部 React AI 日记立即 / 定时生成会被保护性禁用，因为旧 `/api/chat` 会自动附带全部对 AI 可见日记，且没有无副作用草稿模式；这不会影响用户手写日记 CRUD 或旧 FastAPI 主聊天原有的受权限控制日记 / 留言工具写入。
- Android 完全本机模式可保存 MCP，但不能在手机上启动桌面 stdio；连接 FastAPI 后可执行和审计。
- Android 完全本机模式尚无真实往来服务；联系人审批、封禁、安全检查和投递需要连接 FastAPI。
- 会客厅当前仅提供规则与席位布局预览、本机偏好保存、FastAPI 一次性邀请码入口及既有归档读取。完全本机模式不能申请或读取服务器归档，界面会要求连接后端；生成邀请码时只有主持人格和可见范围进入当前 FastAPI 请求。归档总结线路、联网和记忆开关目前仅保存在本机，Relay 接通前不生效。真实席位、提题、投票、正式计时、主持人格唤醒及新归档状态机均仍待迁移，页面不得把预览值或旧归档冒充实时房间状态。
- v0.2.3 已收录字体、日记 / 留言板 / 梦库、自动唤醒与子代理改动，固定签名 Release 的公开附件已复核；真实 Android 手机验收仍未完成。
- 云芽庭院与全部游戏按用户要求暂不迁移，不以空入口冒充完成。
